# Composition-Based Machine Learning for Young's Modulus Prediction

Reproducibility repository accompanying the manuscript **“Composition-Based Machine Learning for Young’s Modulus Prediction with Formula-Grouped Evaluation.”**

This public repository contains the publication scripts, reported tables, supporting outputs, figures and the versioned reproducibility-data archive. Versioned releases are prepared for long-term archival in Zenodo.

## Study overview

This repository contains a composition-only machine-learning workflow for predicting Young's modulus from Materials Project elastic data. The reported analysis:

- calculates Young's modulus from Voigt-Reuss-Hill bulk and shear moduli;
- applies explicit physical and target filters;
- generates 138 Magpie elemental-property and stoichiometric descriptors;
- fits missing-value and correlation preprocessing on training rows only;
- evaluates a fixed XGBoost model with cross-validation, a random test split, repeated random splits and a reduced-formula-grouped split;
- compares XGBoost with fixed median, Ridge, Random Forest and Roost models on the same held-out records; and
- reports gain-based feature importance and SHAP explanations.

## Data availability

The raw Materials Project export is not stored in this repository. The local input expected by the main script is `data/raw/mp_elastic_raw.json`.

The analysed snapshot contained 13,283 elastic-property records before filtering. The versioned reproducibility archive is available at `data/NEW_V1_reproducibility_data_v1.0.0.zip`.

The archive contains the final processed datasets (`mp_elastic_clean.csv`, `mp_features.csv` and `composition_groups.csv`), the data-cleaning report, and the exact random and reduced-formula-grouped Roost split files used in the reference analysis. The processed files can also be regenerated by `pipeline.py` from an authorised Materials Project input snapshot. Materials Project API credentials and the raw JSON export are not included. Never commit a Materials Project API key.

## Environment

Python 3.10 or 3.11 is recommended. Create a clean environment and install the listed packages:

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The requirements file records the compatible package ranges used by the publication workflow.

## Reproduce the XGBoost analysis

From the repository root:

```bash
python src/pipeline.py \
  --raw-data data/raw/mp_elastic_raw.json \
  --output-root runs
```

Use `--cpu-only` when CUDA is unavailable. Each run is written to a new timestamped directory and does not overwrite earlier results.

The completed reference run produced:

| Evaluation | R² | RMSE log10(E) | MAE log10(E) |
|---|---:|---:|---:|
| Random 80:20 test | 0.8264 | 0.1667 | 0.1058 |
| Reduced-formula-grouped test | 0.8235 | 0.1750 | 0.1106 |

Five-fold cross-validation on the nominal training partition produced mean R² = 0.8074 with standard deviation 0.0137.

## Reproduce the fixed baseline comparison

After running `pipeline.py`, provide the generated `processed` directory:

```bash
python src/compare_models.py \
  --processed-dir runs/<RUN_ID>/processed \
  --output-dir runs/<RUN_ID>/model_comparison
```

All models use the same records, target, candidate descriptors, split definitions and training-fitted preprocessing within each partition. The baseline settings were fixed without hyperparameter optimisation.

## Roost comparison

Prepare the exact Roost partitions with:

```bash
python src/prepare_roost_data.py \
  --processed-dir runs/<RUN_ID>/processed \
  --output-dir runs/<RUN_ID>/roost
```

The reference calculation used the Aviary implementation at commit:

```text
3f4db21c2b807ebe993f02d8ba13aafbdd7e07a1
```

After installing Aviary in a separate environment and checking out that commit,
run both partitions with:

```bash
python src/run_roost.py \
  --aviary-dir /path/to/aviary \
  --roost-data-dir runs/<RUN_ID>/roost \
  --python /path/to/aviary-environment/python
```

Each random and grouped model was trained for 100 epochs with one model, L1 loss, data seed 42 and a validation partition drawn only from the nominal training records. Roost used no Magpie descriptors or study-specific sample weights. The resulting scores are retained in `results/tables/table7_same_data_model_comparison.csv`.

## Reproducibility safeguards

- The target and target-derived elastic columns are excluded from the predictor matrix.
- Descriptor retention, median imputation and correlation filtering are fitted using training rows only.
- The grouped test contains no reduced formula occurring in its training partition.
- Random seeds and model parameters are explicit in the source files.
- Results are written to new run directories to prevent accidental overwriting.
